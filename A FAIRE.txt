CONCEPTION PROPOSEE PAR NONO LE 30/08 : ICONES DE NIVEAU PAR ETHNIE
=========================================================================
Constat de depart : les icones de niveau du livre High Elf ne sont pas celles des autres
livres. Le schema d avance des Elfes utilise des glyphes propres (symboles planetaires
colores), pas les icones generiques.

PROPOSITION : un repertoire generique (NIV) et la possibilite, pour l ethnie, de designer
un repertoire particulier (NIV_HELF par exemple) via une option dans la declaration de
l ethnie. Option absente = on cherche dans NIV.

CE QUI PLAIDE POUR : LE CODE A DEJA CE PATRON. CheminRaceImage() dans chargerace.pas
resout les images d ethnie via ConstCheminImageRace = '\DATABASE\BOOKS\%BOOK%\PICTURE\
SPECIE\', ou %BOOK% (ConstLivre) est substitue par le livre de l ethnie. Les icones de
niveau sont les DERNIERES images encore figees sur un repertoire unique
(ConstCheminImageNiveau = '\PICTURES\NIV\').

TROIS POINTS A TRANCHER AVANT DE CODER :

1. ETHNIE OU LIVRE ? Les icones de niveau sont dessinees PAR CARRIERE, et une carriere
   n est pas liee a une seule ethnie. Dans WinMetier l arbre est carriere -> niveaux, sans
   aucun contexte d ethnie ; pdfmetier genere une fiche de carriere, sans ethnie non plus.
   Et le Smith-priest of Vaul est declare pour DEUX ethnies ("High Elf, Wood Elf").
   Trois options :
     (a) option sur l ethnie comme propose, et repli pur et simple sur NIV partout ou
         l ethnie n est pas connue (WinMetier et la fiche PDF de carriere gardent donc les
         icones generiques). Simple, jamais ambigu.  <- la plus sure
     (b) option sur l ethnie, et dans WinMetier on la resout via les ethnies qui donnent
         acces a la carriere : marche quand elles sont d accord, ambigu sinon.
     (c) option sur le LIVRE, comme les images d ethnie le sont deja : jamais ambigu, mais
         faux pour un livre melant carrieres elfiques et humaines. High Elf Player s Guide
         est entierement elfique, donc ca marcherait ici et pas forcement ailleurs.

2. LA TImageList EST CHARGEE UNE SEULE FOIS, a l ouverture de la fenetre, et les grilles et
   l arbre stockent LE NUMERO DE NIVEAU comme index dans cette liste
   (ImageIndex := StrToIntDef(Grid.Cells[...], -1)). On ne peut donc pas se contenter de
   changer un chemin : il faut soit recharger la liste a chaque changement d ethnie, soit
   charger LES DEUX jeux dans la meme liste et decaler l index (0-7 generique, 8-15
   elfique). La seconde solution est plus stable mais impose que la cellule porte l index
   decale, plus le numero de niveau brut.

3. CONVENTION DU PIXEL [1,1] A RESPECTER. ChargeImageArrayColor() prend la couleur du cadre
   dans le pixel en haut a gauche de l icone. Toute image deposee dans NIV_HELF doit suivre
   cette convention, sinon les cadres de l arbre seront faux.

Les libelles ont ete realignes sur le Rulebook p.240-242 le 28/08/2026. Deux
anomalies subsistent dans ces memes blocs, volontairement laissees en l'etat :

  * <TypSpell> vaut "Minor Magic" pour les 25. Les autres familles portent le nom
    du livre ; ici ce serait "Petty Magic". A trancher avant de toucher, parce que
    la valeur peut etre lue ailleurs dans le code.
